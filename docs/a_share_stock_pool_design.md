# A股选股池设计

## 目标

选股池不是简单股票清单，而是一个可复盘的研究对象集合。每个标的必须有入池理由、主题标签、复盘频率、退出条件和数据质量状态，方便 R&D agent 持续判断自己哪里错、哪里需要优化。

## 推荐分层

| 层级 | 用途 | 入池条件 | 出池/降级条件 |
| --- | --- | --- | --- |
| 候选池 | 收集线索 | 主题明确、有催化或行业变化，且数据源能覆盖 | 两周内无法形成可验证假设 |
| 观察池 | 周度验证 | 具备基本面/技术面/资金面至少两个维度证据 | 连续两轮研报与走势偏离且无法解释 |
| 核心池 | 高强度跟踪 | 多周期评分稳定、降级少、逻辑和风险价位清晰 | 基本面假设破坏、数据质量恶化或模型持续错判 |
| 剔除池 | 保留反例 | 明确不适合当前系统，但可做 badcase 训练 | 重新出现有效催化或数据覆盖改善 |

## 每只股票应保存的字段

| 字段 | 说明 |
| --- | --- |
| `ticker` / `name` | 标准代码和中文名 |
| `pool` | 候选池、观察池、核心池、剔除池 |
| `theme` | 产业主题，例如 AI 终端、半导体材料、算力网络 |
| `role` | 在组合里的角色，例如 成长弹性、国产替代、稳健科技、周期拐点 |
| `thesis` | 当前研究假设，一句话即可 |
| `catalyst` | 下一次需要验证的事件，例如财报、订单、政策、价格、行业景气 |
| `risk` | 关键失效条件 |
| `cadence` | 默认周五复盘；核心池可增加盘中/日频监控 |
| `data_quality` | 是否存在数据源降级、缺字段、PDF/日志不一致 |

## 后续落地顺序

1. 在 SQLite 增加 `universe_members` 表，把 `config.py` 中的静态股票池迁移为可编辑数据。
2. 增加候选池导入脚本，支持从 CSV/Excel 批量导入主题、催化和备注。
3. 增加“入池/升级/降级/剔除”事件表，记录每次池层级变化的原因。
4. 把周度评分和降级次数变成升级/降级建议，而不是人工手看所有结果。
5. 接入公告、解禁、融资融券、股东户数等事件源后，对核心池增加事件风险面板。
